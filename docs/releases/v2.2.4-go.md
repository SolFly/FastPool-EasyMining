FastPool EasyMining is a self-hosted NiceHash EasyMining controller with a native Go server, SQLite ledger, and embedded browser dashboard.

### Included

- Manual solo package and team-share purchases, plus interval, price, odds, and multi-level team strategies.
- Continuous buying with editable spending/purchase progress targets and global spending controls.
- Separate BTC and USDT markets, wallets, limits, and accounting.
- Personal team contributions and rewards, daily profit & loss, BTC/BCH/LTC/DOGE/ZEC quantities, and USD/EUR display estimates.
- Saved payout destinations, configuration import/export, optional Telegram purchase alerts and daily reports, and purchase diagnostics.
- GitHub Actions for Go race tests/vet, JavaScript regressions, Docker startup checks, and tested release assets.

### Fix in 2.2.4-go

Live arming now checks the same current ledger records as account sync and purchase guards. Superseded team execution aliases remain available for audit without causing a contradictory spending-verification hold after current history has verified. Current uncertain purchases and real ownership/spending checks retain their protections. The SQLite write coordination and account sync recovery fixes from preceding releases are included.

### Downloads

- `fastpool-easymining-linux-amd64`: static Linux x86-64 executable with the web UI embedded. Run `chmod +x fastpool-easymining-linux-amd64`, then `./fastpool-easymining-linux-amd64 --version`.
- `fastpool-easymining-v2.2.4-go.zip`: installable Go distribution with the Linux executable, Docker files, Go source, documentation, and screenshots.
- `FastPool-EasyMining-GitHub-v2.2.4-go.zip`: full source package, including workflows, tests, vendored dependencies, and MIT license.
- `SHA256SUMS`: checksums for the executable, both packages, and build metadata. Place all files in one directory and run `sha256sum --check SHA256SUMS`.
- `BUILD_INFO.json`: version, source commit, and target information.

### Installation and upgrade

Follow the repository README. Existing Docker users should replace application files in the original installation directory, keep `.env` and the existing data volume, then run `docker compose up -d --build --force-recreate easymining`. Do not remove the data volume during an upgrade. The server starts paused and disarmed: sync, review settings, arm, and start explicitly.

The hosted paper demo uses simulated data. Tests and smoke checks use controlled responses and temporary state; they do not place funded NiceHash purchases or send Telegram messages. Fiat values are display estimates, not executed exchanges.
